# 0002 — Per-persona LoRA fine-tuning for likeness consistency

- Status: Accepted
- Date: 2026-06-09
- Depends on: [ADR-0001](0001-photo-conditioned-likeness.md)

## Context

Given photo-conditioned likeness (ADR-0001), we needed a mechanism to make
illustrations consistently resemble the *same* child across every page and
across future Stories. Options: reference-image multimodal models (no training),
face-identity adapters (no training), or per-persona LoRA fine-tuning.

## Decision

Each Persona gets its own **LoRA fine-tune** trained on the uploaded photos
(Flux-family base model). Illustrations are generated by composing the persona's
LoRA(s) with a per-page scene prompt.

## Consequences

- **Positive:** Best achievable likeness consistency and quality — the strongest
  version of the core hook.
- **Negative / load-bearing facts:**
  - **Persona creation is async and paid.** Training takes minutes and costs GPU
    time, so persona creation is a background job with a "ready" notification —
    not an instant operation. UX and data model must reflect a `training` →
    `ready` / `failed` persona lifecycle.
  - **Per-child model weights are stored** alongside the (already sensitive)
    photos — more data to secure and to hard-delete on request (see ADR-0001).
  - Multi-persona scenes (baby + parent in one illustration) require composing
    multiple LoRAs, which is harder than single-subject generation — a known
    risk to validate early.
  - Cost per persona is now a real unit-economics input to pricing.
