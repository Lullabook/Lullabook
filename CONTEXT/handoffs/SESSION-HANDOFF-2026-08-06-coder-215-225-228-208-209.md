### #215 (local 204) — $20 live fal.ai spend cap, fail-closed — HONEST GAP CLOSED

The previous lane check was not a durable reservation: `reserve()` only read
the ledger, and the ledger row was written **after** the provider call
returned. A crash mid-call could spend past the cap silently.

Now `reserve()` creates a `reserved` cost-ledger row keyed by the attempt's
idempotency key, and the live training path flushes that row through
`persistProviderSpendState()` **before** the provider boundary; `settle()`
transitions it to `succeeded` (hold, with the provider job id) or
`failed`/`cancelled` (release).
Settled rows are terminal; double-settle and unknown-key settle throw.

- `src/services/provider-cost-metering.ts` — `"reserved"` added to
  `ProviderAttemptOutcome` + `recordAttempt` allow-list; new `settleAttempt()`
  (only `reserved` → terminal, once).
- `src/services/live-fal-spend-cap.ts` — durable `reserve()`, new `settle()`,
  `idempotencyKey`/`personaId` in input.
- `src/services/fal-lora-training.ts` — live path: reserve → submit →
  settle(succeeded|failed). Dev-only path unchanged (`recordAttempt`).
- `tests/204-live-spend-cap.test.ts` — durability, idempotent replay,
  settle-to-succeeded with job id, terminal failed-row guards, and the
  pre-provider durable-flush integration test. 11 tests pass.

Acceptance criteria all met: cap-crossing rejected pre-boundary with nothing
reserved; unknown route rejected (never zero); ≥$18 emits `spend_checkpoint`
naming remaining budget; no `LIVE_PROVIDER_RUN_APPROVED=true` rejected
pre-boundary; failures release; cap from config.
